# Constellation Element Book — Volume 2: FM Modules 2027 (rollout order)

**Version:** 1.0 — 4 July 2026 — Status: Proposed. **Common frame (inherited by every module):** own Lovable project; scoped module_service_tokens; registers capabilities and heartbeats; walks the 8 promotion gates; projected_value_usd before activation, realized within a quarter; max two in flight; no start until predecessor passes gate 4; KR-triggered work via Control Plane dispatch post-R5; all AI through the shadow ladder post-T2; each module declares its agent crew — charters, oversight classes, risk ceilings, budgets — in its entry plan.md per docs/agent-architecture.md, lessons flowing through the exchange (competence, never content); queue re-orderable quarterly by demand-board evidence.

## M1 — FM1: Stakeholder Intelligence (live end R3 2026 — the template)
**PRD.** Stakeholder sentiment and engagement tracked in heads and spreadsheets today. Apex: Workplace Experience, Operational Excellence. Success = R3 gates: ≥4 weeks FM1-originated events; ≥1 capability available; ≥1 KR with projected AND realized value; W7.3/7.4 decisions recorded.
**Spec.** Capabilities (manifest-seeded): fm1_stakeholder_profile, fm1_stakeholder_engagement_signal, fm1_stakeholder_sentiment_pulse. Profiles keyed to external_contacts + tenant; time-stamped engagement signals; operator-administered structured pulses (no unsolicited client surveying v1) rolled into weekly measurements via the R3 endpoint. Core asks: token + endpoint, nothing else. NFR: sentiment inferences are source=ai claims with confidence, W7-arbitrated — a human pulse always outranks an inferred one.
**Plan.** In R3. Build: register+heartbeat → profiles → signals → weekly measurement → pulse workflow → gates. Real deliverable: the template (lessons to mem://, module-auth e2e harness). Exit: R3 sign-off.

## M2 — FM7: Knowledge Management (2027-Q1)
**PRD.** The client's knowledge lives in AWIP after W10 but the client can't touch it. Users: client users (first ever) searching the approved corpus, reading memory cards with anchors, exploring the graph; operator curates visibility. Apex: Workplace Experience, Compliance Confidence. Success: ≥5 weekly-active client users; ≥60% of client questions answered grounded with citation; zero lifecycle leaks (tested, not trusted); fidelity panel client-visible.
**Spec.** Capabilities: fm7_knowledge_search, fm7_memory_cards, fm7_digest. Tenant-branded portal: search via a copilot-derived retrieval contract with min_approval_state=approved hard-set and include_memories on; memory cards with page-level citations; read-only local graph; scheduled digests (W8.1 kind fm7.digest). Core asks: one contract row, one token, plus R4b client identity. Client query outcomes feed experience_traces (client thumbs = first client-experience signal in the shadow twin). NFR: no client writes v1 except feedback; every answer carries provenance.
**Plan.** Entry: W10 S2+S3 signed off AND R4b green. Build: client auth + surfaces registry → search → memory cards → graph → digests → feedback → promotion. ~6 wks. Exit: gates + zero-leak e2e matrix + client traces flowing. Risk: scope creep toward a client workspace — v1 read-only; refusals logged as demand signals for FM5.

## M3 — FM3: Performance Management (2027-Q1→Q2, thin by design)
**PRD.** Measurements exist but nobody renders the variance/trend/review ritual an FM leadership team runs. Apex: Operational Excellence, Growth & Value Creation. Success: 100% of active pilot KRs on cadence; monthly pack ≤5 min after close; ≥3 breach-triggered actions through the normal flow.
**Spec.** Capabilities: fm3_measurement_capture, fm3_variance_analysis, fm3_period_pack. Consumes okr_measurements; variance in deterministic views (v_fm3_variance); packs via the report framework; breaches → discussion_actions source=fm3. Core asks: zero beyond the R3 endpoint — the pure-consumer proof the substrate suffices. NFR: no AI in the calculation path; AI only in pack narrative, toggleable.
**Plan.** Entry: FM1 ≥8 weeks of measurements. Build: views → capture UX → pack renderer → breach wiring → promotion. ~4 wks overlapping FM7 tail. Exit: first pack consumed in a real client review. Strategic job: prove a module can be thin — banking the template dividend.

## M4 — FM5: Workflow Automation (2027-Q2→Q3)
**PRD.** Recurring FM work (inspections, client approvals, compliance tasks) runs on email and memory. Clients act for the first time — completing tasks, attaching evidence, approving steps. Apex: Operational Excellence, Cost Efficiency. Success: ≥3 templates live; ≥100 client-completed tasks; SLA-breach rate measured (FM4's baseline); zero client-write incidents in the pre-GA review.
**Spec.** Capabilities: fm5_workflow_templates, fm5_task_execution, fm5_sla_tracking. Versioned workflow definitions (trigger → steps → human gates → evidence requirements); instances on scheduled_jobs (kinds fm5.step_due, fm5.sla_check); evidence attachments enter the W10 pipeline (a client-uploaded photo is governed like everything else); completions/approvals are the first client write paths, each behind its own approval kind where a gate demands it. Core asks: none structural — dispatch and scheduler exist; client_ write policies extend R4b. NFR: pre-GA security review of every client write path; all writes idempotent; evidence provenance mandatory.
**Plan.** Entry: R5 signed off + one internal KR-triggered dispatch ≥4 wks. Build: template model → instance engine → operator template UI → client task surface (extends FM7 portal) → evidence via ingest → SLA views → security review → promotion → GA. ~8 wks. Risk: engine ambition — v1 is linear steps with human gates; branching waits for demand evidence.

## M5 — FM12: Monitoring & Operations (2027-Q3→Q4)
**PRD.** The estate twin describes but doesn't sense — telemetry is the missing behavioural dimension, and Sustainability & ESG is the apex objective with no data source. Apex: Operational Excellence, Sustainability & ESG (first real feed), Risk Reduction. Success: ≥2 telemetry sources flowing; points tagged to twin assets/spaces ≥80%; first ESG KR measured from real data; anomaly findings triaged normally.
**Spec.** Capabilities: fm12_telemetry_ingest, fm12_point_tagging, fm12_ops_findings. Scheduled-pull adapters for BMS/meter exports → time_series_points (BRIN; ADR-0013 Postgres-vs-TSDB decided on measured points/day, revisit ~10M/engagement); pragmatic Haystack-subset tagging as point metadata mapped to tenant_nodes via the resolver; threshold/anomaly checks as a client-scoped check family writing findings → discussion_actions (the sentinel pattern, separate namespace — client ops findings never mix with platform health). NFR: append-only + idempotent on (source, point, ts); anomaly models beyond thresholds born in the shadow ladder; scheduled pulls, no streaming claims — stated plainly.
**Plan.** Entry: W10 S5/S6 signed off; ADR-0013 decided; a tenant with BMS export access. Build: first adapter → point store + tagging → twin joins → dashboards → threshold findings → ESG KR → promotion. ~8 wks. Risk: tagging drudgery — budget operator time under §C3; the resolver + bulk tools carry it or scope shrinks to two systems done well.

## M6 — FM4: Insight & Analytics (2027-Q4 → 2028-Q1)
**PRD.** Five modules emit data no one view unifies, and "prediction" remains unearned. Apex: all seven, by construction. Success: cross-module analytics live; the first predictive KR beats its measured baseline through the full T4 ladder; prediction provenance interrogable to the twin facts behind it.
**Spec.** Capabilities: fm4_cross_module_analytics, fm4_benchmarks, fm4_prediction:<kr> — one registered capability per predictive KR; predictions are capabilities, subject to promotion gates like everything else. Analytics as deterministic marts over the estate twin — no AI in aggregation. Predictive candidates (first: FM5 SLA-breach probability or occupancy-driven cost forecast) trained on twin history, shadow-evaluated on held-out outcomes, canaried on tenant-zero, promoted via ai.component_promotion with baseline-beating evidence. NFR: every surfaced prediction carries model version, training-window hash, baseline comparison, provenance drill-down; cost per prediction visible; a prediction that can't explain its inputs doesn't ship.
**Plan.** Entry: ≥3 modules emitting ≥1 quarter each; T3 complete. Build: marts → benchmarks → FM7 exposure → golden/held-out sets for candidate #1 → shadow → canary → promoted → second candidate only after the first survives a quarter. ~10 wks to first promoted prediction. Exit: baseline beaten and held for a quarter — at which point the AI & Intelligence ring, and the diagram's last aspirational word, reads green.
