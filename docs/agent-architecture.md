# AWIP Agent Architecture — Module Agents, Core Coordination, Self-Learning & Knowledge Sharing

**Version:** 1.0 — 4 July 2026 — Status: Proposed. **Documentation audit:** three fragments exist — docs/agents/team/ (build-time construction personas, not runtime), ADR-0007 (MoE intent: manifest routes, Control Plane dispatches, verifiers gate), and the lessons loop (platform-scoped self-learning). Never documented: the runtime model where each FM module ships specialised agents, Core coordinates and manages, and agents self-learn and share knowledge. This is that missing piece.

## 1. Division of labour
**Core manages** (who exists, budgets, oversight class, kill switch, lesson exchange, events — still NO routing; Rule 4 intact). **Control Plane coordinates** (which agent acts on which KR event, when, with what budget). **Modules specialise** (each ships the small crew its domain needs). **The shadow twin evolves them** (no behaviour change outside the ladder). **The lesson exchange makes them collectively smarter** (§5: competence, never content).

## 2. Agents as manifest citizens
module_agents: agent_key (e.g. fm1.sentiment-analyst, core.memory-extractor), owning_module (scope-checked against the module token), charter (one paragraph: what it does, what it must never do), oversight ∈ operator-approve/operator-review/system-auto/sentinel-watch (ISO 42001 column, per-agent, mandatory at registration), risk_ceiling low/med/high (max discussion_actions risk it may touch), budget_daily_tokens (enforced at pickModel()), status registered/active/paused/retired, current_version_id → ai_component_versions (the ladder pin). module_agent_events append-only (registered, activated, paused, resumed, retired, version_promoted, budget_changed, oversight_changed). **Rules:** registration/heartbeat ride the module contract (heartbeats tagged agent_key); every AI call carries agent_key into ai_usage_log (per-agent cost from day one); **status=paused is the kill switch** — pickModel() and dispatch refuse a paused agent; one click stops it constellation-wide, evented, reversible. Existing AI surfaces (memory extractor, classifiers, morning-review discussants, night agent, overnight runner) backfill as core.* agents — inventory-as-audit. persona-coverage.ts extends to check every runtime agent's charter matches its registry row.

## 4. Self-learning (the lessons loop, generalised per agent)
agent_lessons: agent_key, scope agent/module/shared, kind technique/pitfall/preference/domain_rule, title + body ≤500 chars (injectable), evidence jsonb (experience_trace/event refs — no evidence, no proposal), status proposed/applied/rejected/retired/superseded, effectiveness numeric; agent_lesson_events; unique (agent_key, md5(title)).
**Learned:** a periodic synthesis pass (extending lessons-synthesize, per-agent, night-window, cost-capped) clusters negative-outcome experience_traces and proposes lessons with evidence pointers; the operator tray (existing lessons UI + agent facet) applies/edits/rejects.
**Used:** applied lessons inject into the agent's context at invocation (bounded ranked block, ~10 lessons / ~2k chars, ranked by effectiveness then recency). **A lesson is not a behaviour change outside the ladder:** lessons tune within a promoted component version; anything changing the component itself (prompt rewrite, model swap, threshold move) is a new ai_component_versions candidate and walks the ladder. Lessons = fast human-gated loop; ladder = slow evidence-gated loop; both audited.
**Verified:** effectiveness = normalised before/after outcome delta on matched trace classes; lessons ≤0 over sufficient sample auto-propose retirement (auto_reject_stale generalised); morning review gains a per-agent learning digest. Self-learning without measurement is drift — this is the countermeasure.

## 5. Knowledge sharing (competence, never content)
**The hard rule:** agents share HOW to work (techniques, pitfalls, domain rules) — never WHAT they worked on (client data, engagement content, tenant-identifiable anything). Engagement scoping is an invariant; three structural enforcements: (1) **Redaction at proposal** — title/body pass the e2e-diag redactor plus a tenant-term scrub (tenant names, aliases, node labels in scope); evidence pointers are ids, not payloads — resolving them requires the reader's own RLS rights. (2) **Human gate at promotion** — scope starts agent; promotion to module or shared is an explicit operator action with a diff view; shared promotion re-runs the scrub and requires operator attestation that no client context survives; evented, reversible. (3) **The exchange is pull, not push** — shared lessons land in a read-only exchange view; each module's synthesis pass subscribes, proposing relevant shared lessons into its own agents' trays as candidates, applied or rejected per agent like any local lesson. No silent cross-module injection; adoption is always a local recorded decision. Client data crosses module boundaries only as it always has — canonical facts, events, dispatch payloads, contract-governed and tenant-scoped. **Worked example:** FM7's answer-agent learns (from rejected traces) that drawing-number questions want lexical-first retrieval → applied → effectiveness climbs → promoted to shared after scrub → FM12's synthesis surfaces it to anomaly-spotter's tray → applied there. Two modules, one insight, zero client data moved.

## 6. Core's management surface
/admin/agents (registered in the observability registry): roster (status, oversight, version pin, spend vs budget, lesson counts, last heartbeat); per-agent drawer (charter, applied lessons, effectiveness trend, trace outcomes, pause/resume with reason); exchange tab (shared lessons, provenance, adoption map). Sentinels: agent_budget_exceeded (high; auto-pauses at 120% — the one automated pause, evented), agent_silent (per active agent, cadence-aware), agent_outcome_regression (medium — accepted-rate drops >20% week-over-week), lesson_exchange_scrub_failure (critical — tenant terms found at shared promotion; promotion blocked).

## 7. Governance & safety summary
Every agent: charter + oversight at registration (ISO 42001 evidence, structural); risk ceiling honoured by night rules and dispatch; versioned through the ladder with promotion approvals for high-consequence behaviour; cost-attributed per call; kill-switchable in one click; learning measured and reversible; sharing scrubbed and doubly human-gated. The §C3 throughput budget extends to lesson trays; the effectiveness machinery means trays shrink as agents stabilise.

## 8. Adoption plan (A-track, ~4 wks net-new)
**A1** (rides R3, ~1.5 wks): module_agents + events + kill switch in pickModel()/dispatch; backfill core.* agents; agent_key into ai_usage_log; /admin/agents v0; FM1 registers the first module crew. **A2** (rides T2, ~1.5 wks, fused with the shadow foundation): agent_lessons + synthesis + tray facet + context injection + effectiveness; doc-memory-extract is the pilot learner. **A3** (rides R5, ~1 wk): the exchange (double-scrub promotion, pull-side subscription, adoption map); dispatch honours ceilings and budgets; outcome-regression sentinel. **Standing rules (mem://preferences/ at A1):** every runtime AI behaviour belongs to a registered agent; agents share competence, never content; a paused agent stays paused until a human says otherwise.

## 9. Placement
Slots between the Twin Framework (how agents evolve) and the module element book (each module declares its crew at entry). ADR-0007's MoE is now buildable: the manifest routes, the Control Plane dispatches to registered agents, verifiers gate promotion — and the experts now learn, individually and collectively, under governance that makes the learning auditable.
