# W10 — Corporate Knowledge Ingestion: Technical Specification

**Version:** 1.0 — 4 July 2026 — Status: Proposed. Extends `docs/specs/data-ingestion-module.md` (W9 mechanics remain authoritative). Absorbs W9.2 (CAD) and W9.3 (graph); re-sequences W9.4 after stage 2. House rules apply throughout (withLogger, Idempotency-Key + body-hash, has_role() RLS, events on every mutation, pickModel(), engagement scoping, UK English).

## S1 — Storage & records
**Schema:** ingested_files + records_class (checked enum, default other), retention_policy (fk → retention_policies: key, hot_days, chunks_days, min_approval_for_delete; seeds standard/contract/media/working), revision_of (self-fk), revision_label, legal_hold (default false), bytes_tier (hot/chunks_only/tombstone); legal_hold_audit + set_legal_hold(_file_id,_on,_reason) SECURITY DEFINER admin-gated.
**Behaviour:** revision detection (same normalised filename + different sha → revision_candidate in response; confirm sets revision_of, predecessor → superseded, emits revision_superseded + supersedes graph edge); deterministic classifier (_shared/contracts/records-class.ts; LLM assist for 'other' operator-toggled); retention sweeper (scheduler kind records.retention_sweep, daily 03:10 UTC; hot→chunks_only deletes bucket object keeping sha+chunks+events; chunks_only→tombstone per policy; NEVER touches legal_hold; never deletes rows; dry-run via app_secrets RECORDS_SWEEP_DRY_RUN default true, first two weeks); quotas: tenant_quotas.storage_bytes enforced at ingest-file (413, sentinel at 80%).
**S1.3 Backup & DR (readiness companion §5):** DB RPO ≤24h / RTO ≤8h; bucket second-location copy RPO ≤24h; quarterly restore drill (scratch project, e2e smoke, one held-file round-trip) recorded as qa_checks; platform backup posture verified and documented in docs/runbooks/disaster-recovery.md. **S1 sign-off requires the first recorded drill.**
**S1.4 Observability:** sentinels retention_sweep_silent (daily cadence), legal_hold_delete_attempt (critical); ingest-health storage-tier card.

## S2 — Approval & trust boundary
**Lifecycle:** ingested → pending_review | auto_approved → approved → superseded → archived; quarantined from any state; rejected terminal. Columns lifecycle, approved_by/at, approval_id. document_approval_policies per class (mode auto/operator/four_eyes + auto_conditions jsonb). Seeds: contract/certificate/register/model/drawing → operator; correspondence/media/other → auto (clean parse + lawful basis); four_eyes ships dormant.
**Flow:** ingest-callback evaluates policy on terminal parse → auto_approved (event + condition snapshot) or approval row (idempotent on kind+file_id) + pending_review. Decide flips lifecycle. **Canonical gate:** structured auto-promote gains fourth condition — source document lifecycle ∈ approved states; red-path e2e proves it.
**Approval-aware retrieval:** retrieval_contracts + min_approval_state (any/auto_approved/approved, default approved); match RPCs replaced by _v2 adding min_lifecycle (old signatures as deprecating wrappers one release); ingest-search resolves from the caller's contract; agent surfaces approved, operator-search any with lifecycle badges. CI guard scripts/check-retrieval-approval.ts fails builds on RPC calls bypassing contract-resolved min_lifecycle.
**S2.5 Non-engineering sign-off conditions (companion §§2–3):** S2 sign-off additionally requires an executed DPA with the pilot tenant (or documented tenant-zero exception), the operator-absence runbook (docs/runbooks/operator-absence.md), and review-queue 7-day median wait ≤72h post-backfill.
**Events & sentinels:** submitted_for_review, document_approved, document_auto_approved, document_rejected, document_quarantined, revision_superseded; document_review_backlog (med ≥25 >72h, high ≥100), unapproved_retrieval_attempt (high).

## S3 — Document memory
**Schema:** doc_memories (engagement_id, file_id, chunk_id, anchor jsonb {page, section, heading_path, quote_hash}, kind ∈ obligation/key_date/definition/party/constraint/quantity/decision/other, title, body ≤600 chars, structured jsonb, status proposed/applied/rejected/superseded, confidence, embedding+embed_model, applied_by/at, superseded_by; unique (file_id, kind, md5(title))); doc_memory_events append-only.
**Extraction:** doc-memory-extract runs only after approved/auto_approved; batched with heading context; pickModel() night-cheap; zod-validated JSON; each memory must carry a verbatim quote whose hash verifies against the chunk — no anchor, no memory; caps ≤40 proposals/file + per-run tokens; ai_usage_log job=doc-memory-extract. Revision: new revision approved → extract → matching titles auto-link supersedes; predecessors flip on apply.
**High-consequence rules (companion §6):** key_date and obligation are NEVER auto-applied regardless of class policy — the tray structurally excludes them from bulk-apply. Accuracy eval harness (≥50 hand-labelled fixtures per high-consequence kind, adr-bench pattern) gates every extractor change: precision <95% blocks deploy. Sub-threshold confidence renders a warning chip. Downstream consumers (FM8 reminders) must cite memory + anchor in any generated action.
**Review & retrieval:** /ingest/memories tray (apply/edit/reject, bulk by kind except high-consequence, realtime); applied memories embed and join hybrid as a third RRF leg with contract-tunable memory_boost; hybrid RPC gains include_memories; rows carry hit_kind chunk|memory; memories ship anchors for page-level citation. Fact bridge: key_date/quantity with complete structured → one-click promote to canonical via staged path (source doc_memory:<id>).
**Observability:** doc_memory_backlog (med ≥100 proposed >7d), doc_memory_anchor_failures (high ≥10%/24h); v_doc_memory_adoption KPI view.

## S4 — Knowledge graph (occupies W9.3)
**Schema:** graph_nodes (engagement_id, node_kind ∈ document/doc_memory/tenant_node/capability/okr_node/contact/note, ref_id, label, optional embedding; unique engagement+kind+ref); graph_edges (src, dst, edge_kind ∈ references/supersedes/defines/mentions/applies_to/evidences/contradicts/part_of, status suggested/confirmed/rejected, origin explicit/extracted/structural, anchor, confidence, created_by/confirmed_by; unique (src,dst,edge_kind); backlink index on (dst, edge_kind) where confirmed). graph_events append-only. Nodes are lazy projections; nightly consistency job flags dangling refs (low sentinel).
**Link sources:** explicit — [[wikilinks]] in notebook entries + per-document notes; resolver: exact title → document, else resolve_entity over aliases, else pg_trgm fuzzy with disambiguation popover; unresolved render dashed; parser in _shared/wikilinks.ts, pure + unit-tested. Extracted — extractor emissions + deterministic mention-scanner (drawing numbers, asset codes, space names via aliases, document titles; no LLM); all arrive suggested; backlinks pane shows Suggested (n) with confirm/reject + bulk-by-pattern; kill scanner patterns under 20% confirm-rate. Structural — revisions → supersedes; lineage → evidences; CAD trees → part_of; memory links → defines/evidences; triggers, never suggested.
**Query & UI:** SECURITY DEFINER RPCs graph_backlinks, graph_local (hop cap 3, row cap 500), graph_orphans, graph_hubs; backlinks pane on document pages; local graph (force layout, design-system tints); corpus graph at /ingest/graph. Retrieval leg 'graph' (1-hop evidences/defines expansion pre-fusion) flagged off by default.
**Scale guard:** Postgres until >2M edges/engagement OR 3-hop p95 >2s — ADR-0010 with bench.

## S5 — CAD/BIM adapters (occupies W9.2)
**S5.1 Routing:** ingested_files.parse_quality numeric 0–1 (text density, OCR confidence) — <0.4 excluded from memory extraction, flagged for re-scan. CAD branch tiered: IFC → cad-ifc (ifc-sidecar); DWG/DXF → cad-dwg (ODA→DXF→ezdxf); RVT/RFA/NWD/NWC → cad-aps if tenant APS creds else metadata_only; SKP/STEP/IGES/OBJ/FBX/GLB/LAS/LAZ/E57 → metadata_only + thumbnail; COBie xlsx (sheet-name detected) → adapter:cobie.
**S5.2 IFC sidecar:** Python + IfcOpenShell co-located with markitdown host; HMAC callback, payload type cad_extract; extracts spatial tree (Site→Building→Storey→Space), elements + Psets/Qsets, systems, zones → raw_records/staged → canonical via standard path; every space/asset through resolve_entity_logged with bim_ifc_guid (weight 1.00 authoritative) — match attaches facts to existing tenant_node, confident no-match creates node+alias (source ifc:<file_id>), conflict band → triage. part_of edges mirror the tree; compact per-storey/system digests as searchable chunks. Caps 200k elements (beyond → type summaries + cad_model_truncated event); 5-min heartbeats.
**S5.3 DWG/DXF:** blocks + attributes (TAG/ID pattern) → candidate assets (alias dwg:<file>#<handle>); title blocks (number, revision, discipline) → metadata + references suggestions to specs sharing the number. Geometry not interpreted — stated.
**S5.4 APS (optional per tenant):** creds from app_secrets (fm:<tenant>-scoped naming); Model Derivative job polled via scheduler kind cad.aps_poll → IFC/properties → re-enter Tier A; absent creds → metadata_only + UI notice. No Autodesk spend on AWIP's account.
**S5.5 Viewer:** web-ifc WASM, flagged off, spatial-tree sidebar synced to extracted nodes.
**S5.6 Security/observability:** unprivileged sidecar, per-file cpu/mem/time limits, fuzz corpus in the stage-gate audit; sentinels cad_extract_stuck/failed_burst, aps_poll_dlq.

## S6 — FM tool bridge
**Ontology:** _shared/contracts/fm-ontology.ts — FmSpace/FmAsset/FmSystem/FmTask/FmDocument as typed projections over tenant_nodes + canonical_facts; classification_codes seed table (Uniclass 2015, OmniClass, SFG20) as optional attributes.
**Mappings:** fm_tool_mappings (tenant_id, tool ∈ planon/archibus/maximo/concept/mri/cobie, direction import/export, version, status draft→approved lock trigger mirroring source_mappings, mapping jsonb); approval via approval_queue kind fm.mapping_approval.
**COBie first:** adapter:cobie import (COBie 2.4 sheets → staged; Component→Space → part_of edges; Document sheet links to ingested files); fm-export-cobie (operator JWT + Idempotency-Key; approved canonical picture → COBie 2.4 workbook in private fm-exports bucket, signed URL, fm_export_runs + events, deterministic ordering for diffability).
**Native connectors (one at a time, tenant-gated):** scheduled-pull adapter per tool (Planon SDK/OData, Archibus WS, Maximo OSLC, Concept API, MRI API) + push fn implementing FM_PUSH_CONTRACT (idempotent per (tool, external_id, field, value_hash); fm_push_events; DLQ sentinel fm_push_dlq_growth high). Build trigger per connector: a live tenant running that tool. Creds per tenant in app_secrets via get_app_secret.
**Reconciliation loop:** import → staged → canonical; resolver matches on asset_code / bim_ifc_guid / new seeded fm_external_id (weight 0.95); differences = normal fact_conflicts with source-system facet; approved winners flag export_pending where the FM tool held the losing value; export run clears flags, every push idempotent + evented; first exports against the tool's sandbox/UAT where one exists.
**Isolation:** tenant from token/JWT claim, never body; two-tenant FM e2e (tenant A's creds can never emit tenant B's assets — asserted); stage-6 gate requires isolation audit green.
