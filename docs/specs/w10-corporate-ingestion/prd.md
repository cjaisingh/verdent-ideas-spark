# W10 — Corporate Knowledge Ingestion: PRD

**Version:** 1.0 — 4 July 2026 — Status: Proposed. Builds on `docs/specs/data-ingestion-module.md` (W9.0/9.1 shipped; absorbs reserved W9.2 CAD and W9.3 graph; re-sequences W9.4 OAuth after stage 2).

## 1. Problem
An FM engagement runs on documents: leases, O&Ms, asset registers, drawings, BIM models, surveys, contracts, certificates, COBie files, BMS exports. W9 parses office formats and canonicalises structured feeds — but five gaps stop it being corporate ingestion: (1) **no trust boundary** — a parsed file is immediately retrievable by every agent; no distinction between a dropped PDF and the approved current fire strategy; (2) **no document lifecycle** — parse status, not business status; no revisions, retention classes, legal hold; (3) **no memory** — a 200-page lease becomes 400 chunks, not knowledge; obligations and key dates re-discovered per query; (4) **no relationships** — documents reference each other constantly (drawing ↔ spec ↔ O&M ↔ asset ↔ space) but are stored isolated; the Obsidian model (typed links, backlinks, unlinked mentions, local graph) is the right UX and doesn't exist; (5) **CAD is metadata-only and FM tools unreachable** — DWG/RVT/IFC store a filename; the richest FM data a client owns is invisible; validated facts cannot flow to/from the client's CAFM/IWMS/CMMS.

## 2. Vision
Any file a client organisation produces becomes governed, connected, remembered knowledge — flowing both ways between AWIP and the FM tools the client already runs. A file arrives → stored, deduplicated, classified, parsed → enters a document lifecycle with explicit approval → key knowledge extracted into approved memory → woven into a graph of documents, spaces, assets, people, OKRs → if a drawing/model, its geometry-adjacent data (spatial tree, schedules, Psets, COBie) canonicalised like any structured source → validated facts map field-by-field to the client's FM tools, COBie as universal interchange, native connectors where they earn their keep.

## 3. Users & jobs
**Operator:** onboard an estate in days; trust agents cite only approved current material; see connections before a workshop. **Downstream agents:** retrieve only what trust policy allows; prefer memory over raw chunks; traverse relationships. **FM client stakeholder:** hand over the SharePoint dump, IFC models and Planon export; get back a reconciled validated picture — and push corrections into Planon, not a spreadsheet. **Compliance owner:** prove retention, approvals, legal hold, DSARs.

## 4. Goals & metrics
G1 trust boundary: 100% of agent retrievals approval-aware by end stage 2. G2 lifecycle: ≥95% of new ingests class+state assigned; backfill ≥80%. G3 memory: ≥30% of grounded answers memory-grounded within 60 days of stage 3. G4 graph used: ≥10 operator sessions/wk touching backlinks/graph; orphans <20%. G5 CAD: ≥70% of IFC and ≥50% of DWG/RVT yield canonical facts at pilot. G6 FM loop: one round-trip (register in → reconciled → corrections exported) ≥500 assets, 1 tenant, 1 tool. G7 cost: 0 months over budget.

## 5. Feature narrative
**5.1 Storage & records (S1):** records class per file (contract/drawing/model/oandm/certificate/survey/correspondence/register/media/other) with default retention; revision chains (re-upload supersedes); legal hold freezing deletion; tiered retention (hot → chunks-only → tombstone); per-tenant storage quotas. **5.2 Approval & trust (S2):** lifecycle ingested→pending_review→approved→superseded→archived (+quarantined/rejected); approval_queue kind ingest.document_approval; class-based policy (low-risk auto on clean parse + lawful basis; contracts/certificates/registers/models/drawings operator-approved; four_eyes flag ships dormant); retrieval contracts learn min_approval_state — agent surfaces default approved; canonical promotion gains a fourth condition (source document approved). **5.3 Document memory (S3):** post-approval extraction proposes typed doc-memories (obligation, key_date, definition, party, constraint, quantity, decision) each with a verbatim hash-verified anchor; operator tray applies/edits/rejects; applied memories join hybrid retrieval as a boosted leg and bridge to canonical facts where fact-shaped; memories supersede with document revisions. **5.4 Obsidian-style relationships (S4):** graph over documents, memories, tenant_nodes, capabilities, OKR nodes, contacts; typed edges (references, supersedes, defines, mentions, applies_to, evidences, contradicts, part_of); three link sources — explicit [[wikilinks]] resolved via the entity resolver, extracted suggestions (deterministic mention-scan + extractor emissions, confirm/reject = governable unlinked mentions), structural (revisions, lineage, CAD trees); backlinks pane + local graph + corpus graph; engagement-scoped always. **5.5 CAD & BIM (S5):** tiered honestly — Tier A IFC (IfcOpenShell sidecar: spatial hierarchy, Psets/Qsets, schedules → canonical facts; spaces/assets resolved via bim_ifc_guid authoritative descriptor; part_of edges; searchable digests); Tier B DWG→DXF (ODA converter; layers, blocks, attributes → candidate assets; title blocks → metadata + auto-links); Tier C RVT/NWD via tenant-licensed APS else metadata-only, stated plainly; Tier D meshes/point clouds metadata+thumbnail; COBie parser ships here; optional web-ifc viewer, flagged. **5.6 FM tool mapping (S6):** compact FM ontology (Space, Asset, System, Task, Document; Uniclass/OmniClass/SFG20 as optional tags); per-tenant per-tool field mappings approved like source_mappings; COBie 2.4 import AND export first (universal); native connectors (Planon, Archibus, Maximo, Concept, MRI) one at a time, gated on a live tenant per tool; reconciliation is the product — import → resolver match (new fm_external_id descriptor) → conflicts in existing triage → approved winners flagged export_pending → idempotent evented push back.

## 6. Non-goals
**Honesty note first:** "full corporate ingestion" is **file-shaped until W9.4** — email/Teams, the largest corporate knowledge source, arrives with OAuth pulls in 2027, deliberately post-trust-boundary; the correspondence class is fed by forwarded/exported files until then. Also out: geometry computation (clash/QTO/model checking); cross-engagement corpus; real-time BMS streaming; public graph API; document authoring/editing.

## 7. Principles
Approval before retrieval for agents. Extraction proposes, operator disposes. Provenance always. Open formats first (IFC before RVT, COBie before native). Honest tiers. Engagement-scoped, pickModel()-routed, idempotent — house rules unchanged.

## 8. Dependencies & assumptions
R4 supplies quotas + two-tenant harness. Sidecar host decision resolves in R1 (IFC container co-locates). APS assumes tenant-licensed credentials. Graph is Postgres tables until >2M edges/engagement or 3-hop p95 >2s (ADR-0010).

## 9. Release criteria (programme)
Pilot estate (≥500 files incl. ≥20 IFC/DWG) ingested, ≥95% lifecycle-assigned; agent surfaces approved-only; ≥200 applied doc-memories with anchors; graph connected (orphans <20%); IFC extraction created/matched ≥300 tenant_nodes via resolver; one CAFM round-trip (≥500 assets) with zero cross-tenant findings in the stage-gate audit.
